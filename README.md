# KAPRI-LAB

Автоматическая лаборатория проверки проекта [К.А.П.Р.И.](https://github.com/loslam-del/K.A.P.R.I).

## Что делает текущая версия

- Забирает актуальный публичный исходный код К.А.П.Р.И.
- Проверяет сам отчётчик и Android package identity.
- Проверяет, что applicationId остаётся `com.example.screenai`.
- Запускает Android unit tests и собирает debug APK в GitHub Actions.
- Сохраняет Markdown/JSON отчёт и APK как artifacts.
- Запускается вручную, при изменениях в лаборатории и ежедневно ночью.

## Ночной запуск

Открой **Actions → KAPRI Lab Check → Run workflow**. После завершения открой artifacts запуска: там будут отчёт и APK, если сборка прошла.

Ежедневный запуск также настроен по расписанию GitHub Actions. GitHub выполняет сборку в облаке, а не на телефоне.

## Совместимость обновлений Android

Лаборатория проверяет, что `applicationId` К.А.П.Р.И. не изменился. Это только одна часть совместимости: Android также требует совместимую подпись APK. Текущая сборка `assembleDebug` на новом GitHub runner может получать другой debug-сертификат при каждом запуске, поэтому Android может отклонять APK как конфликтующий.

В исходном репозитории К.А.П.Р.И. добавлена поддержка постоянной release-подписи через GitHub Secrets. Пока эти секреты не настроены, CI выдаёт только debug APK, который не следует считать обновлением поверх установленной версии. См. [руководство по подписи и миграции](docs/android-updates.md).

## Ограничения

- GitHub Actions не управляет физическим телефоном и не запускает Geometry Dash на нём.
- Для реальных тестов нужен отдельный Android Mobile Runner и разрешения, которые пользователь выдаёт вручную.
- Android не позволяет лаборатории молча подтверждать установку APK или специальные разрешения.
- Успешная сборка не доказывает, что приложение правильно работает на телефоне.
- AI-авторемонт и автоматическое слияние изменений не включены.

Никогда не добавляй API-ключи или keystore в код, README, issue или чат. Для release-подписи используй GitHub Actions Secrets.
